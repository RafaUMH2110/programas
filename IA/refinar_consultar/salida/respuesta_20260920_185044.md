# Análisis Técnico Completo: Pérdida de Asignaciones de Spaces en macOS al Cambiar entre Displays

## 1. Razones Técnicas de la Pérdida de Asignaciones de Spaces

### Arquitectura de Gestión de Displays en macOS

El problema que experimentas es un comportamiento inherente al diseño arquitectónico de macOS relacionado con cómo el sistema gestiona los **Spaces** (Escritorios Virtuales) y las configuraciones de displays.

#### Concepto Fundamental: Display-Bound Spaces

En macOS, cada **configuración física de display** genera un contexto único identificado por:

- **Display UUID**: Identificador único del monitor
- **Resolution Profile**: Perfil de resolución y escala
- **Arrangement ID**: Identificador de la disposición de pantallas
- **Color Profile**: Perfil de color asociado

Cuando cambias entre el display integrado del MacBook y el monitor externo en modo clamshell, macOS interpreta esto como **dos configuraciones de display completamente diferentes**, no como variantes de la misma configuración.

#### El Sistema de Persistencia de Spaces

macOS almacena las asignaciones de aplicaciones a Spaces en una base de datos gestionada por el daemon `Dock.app` y `WindowServer`, específicamente en:

```
~/Library/Application Support/Dock/
~/Library/Preferences/com.apple.spaces.plist
~/Library/Preferences/com.apple.dock.plist
```

**Problema central**: Estas asignaciones están vinculadas al **Display Configuration Hash**, que cambia completamente cuando:
- Pasas del display interno al externo
- Cambias la resolución
- Modificas el arrangement de displays

### Comportamiento Específico en Modo Clamshell

En modo clamshell:

1. **Desconexión del display interno**: El sistema desactiva completamente el controlador de display interno
2. **Transferencia de contexto**: Intenta migrar Spaces al monitor externo
3. **Reinicialización de Spaces**: Debido a las diferentes características (resolución, DPI, tamaño físico), los Spaces se **reconstruyen** en lugar de transferirse
4. **Pérdida de metadata**: Las asignaciones de aplicaciones son tratadas como metadata dependiente del contexto de display original

## 2. Gestión de Spaces y Configuraciones de Display en macOS

### Sistema Mission Control y Window Server

El sistema de Spaces forma parte de **Mission Control**, que interactúa directamente con:

- **WindowServer**: Compositor de ventanas de bajo nivel
- **Dock Process**: Gestor de Spaces y aplicaciones
- **SkyLight Framework**: Framework privado que gestiona la composición de ventanas

```bash
# Procesos involucrados
ps aux | grep -E "(WindowServer|Dock|ControlCenter)"
```

### Ciclo de Vida de Spaces con Cambios de Display

#### Secuencia cuando conectas el monitor externo (modo clamshell):

1. **Hot-plug detection** → `IODisplayConnect` detecta el nuevo display
2. **Display negotiation** → Se establece comunicación EDID/DisplayPort
3. **Configuration switch** → WindowServer reconfigura el contexto gráfico
4. **Spaces migration attempt** → Se intenta migrar Spaces existentes
5. **Application redistribution** → Las aplicaciones se redistribuyen según heurísticas del sistema
6. **Metadata reset** → Las asignaciones específicas se pierden

#### Secuencia cuando desconectas (vuelves al display interno):

1. **Display disconnect event** → El sistema detecta la desconexión
2. **Fallback to internal** → Reactivación del display interno
3. **Spaces reconstruction** → Los Spaces se reconstruyen con configuración por defecto
4. **Window gathering** → Las ventanas se agrupan automáticamente

### Diferencias con Extended Display

Si usaras configuración extendida (que no es tu caso), macOS:
- Mantendría **Spaces independientes por display**
- Preservaría mejor las asignaciones porque cada display tendría su propio conjunto persistente
- Usaría el display interno como "ancla" de persistencia

## 3. Relación entre Cambios de Display y Persistencia de Spaces

### System Integrity Protection (SIP) y Limitaciones

Desde macOS Big Sur, Apple endureció las políticas de persistencia:

```bash
# Verificar estado de SIP
csrutil status
```

Las bases de datos de configuración están **protegidas** y el sistema:
- Resetea configuraciones en cambios "mayores" de hardware
- Considera el cambio de display como un cambio de contexto de trabajo
- Prioriza la "experiencia limpia" sobre la persistencia absoluta

### Formato de Almacenamiento de Asignaciones

Las asignaciones se almacenan en formato de property list binario:

```bash
# Convertir a formato legible (requiere SIP deshabilitado para modificar)
plutil -convert xml1 ~/Library/Preferences/com.apple.spaces.plist -o - | less
```

**Estructura clave** (simplificada):
```xml
<key>SpacesDisplayConfiguration</key>
<dict>
    <key>Display-UUID-XXXX</key>
    <dict>
        <key>Spaces</key>
        <array>
            <dict>
                <key>id64</key>
                <integer>SPACE_ID</integer>
                <key>windows</key>
                <array>
                    <integer>WINDOW_ID</integer>
                </array>
            </dict>
        </array>
    </dict>
</dict>
```

El **Display-UUID-XXXX** cambia entre interno y externo, causando la desvinculación.

## 4. Detalles Específicos del M4 Pro

### Apple Silicon y Gestión de Displays

El M4 Pro incorpora características específicas:

#### Display Engine Integrado

- **Unified Memory Architecture**: La memoria compartida afecta cómo se gestionan los buffers de display
- **Dynamic Caching**: El motor de display tiene caché dinámica que se resetea en cambios de configuración
- **Hardware-Accelerated Composition**: La composición acelerada por hardware requiere reinicialización completa del pipeline

#### Metal y WindowServer

```bash
# Información del sistema de display
system_profiler SPDisplaysDataType
```

En M4 Pro, WindowServer utiliza:
- **Metal 3**: Para composición de ventanas
- **Display Streams**: Streams independientes por display físico
- **ProMotion Support**: Adaptación de refresh rate que requiere contextos separados

### Diferencias con Intel

En Macs Intel antiguos:
- Usaban `IOGraphics` framework (legacy)
- Tenían persistencia "más laxa" de configuraciones
- El compositor era menos estricto con resets de contexto

En Apple Silicon (M4 Pro):
- Usa `AGXAccelerator` y frameworks modernos
- Mayor aislamiento entre contextos de display
- Política de "clean slate" más agresiva en cambios de hardware

## 5. Soluciones Prácticas y Mitigaciones

### Solución 1: Configuración del Sistema (Básica)

#### Ajustes en Preferencias del Sistema

```bash
# Desactivar la reorganización automática de Spaces basada en uso reciente
defaults write com.apple.dock mru-spaces -bool false

# Reiniciar Dock para aplicar cambios
killall Dock
```

**Configuración manual**:
1. Ve a **Configuración del Sistema** → **Escritorio y Dock**
2. Desactiva: **"Reorganizar espacios automáticamente según el uso más reciente"**
3. Mantén activado: **"Los monitores tienen espacios independientes"** (aunque uses uno solo, ayuda con la gestión)

#### Asignaciones Persistentes por Aplicación

Para cada aplicación crítica:
1. Abre **Mission Control** (F3 o gesture de tres dedos)
2. Arrastra la aplicación a la barra superior al Space deseado
3. Click derecho en el icono del Dock → **Opciones** → **Asignar a** → **Este escritorio**

**Limitación**: Esto puede perderse aún con cambios de display, pero reduce la frecuencia.

```applescript

-- Script: restore_spaces.scpt
-- Restaura aplicaciones a Spaces específicos

    -- Esperar a que el display esté estable

#### Detección Automática de Cambios de Display

Usa **sleepwatcher** o **hammerspoon** para ejecutar el script automáticamente:

**Opción A: Hammerspoon** (Recomendado)

```bash
# Instalar Hammerspoon
brew install --cask hammerspoon
```

Configuración `~/.hammerspoon/init.lua`:

```lua
-- Configuración de Hammerspoon para gestión de Spaces

-- Tabla de configuración de aplicaciones por Space
local appSpaceConfig = {
    ["Mail"] = 1,
    ["Messages"] = 1,
    ["Slack"] = 1,
    ["Safari"] = 2,
    ["Google Chrome"] = 2,
    ["Visual Studio Code"] = 3,
    ["Terminal"] = 3,
    ["iTerm2"] = 3,
    ["Microsoft Word"] = 4,
    ["Microsoft Excel"] = 4,
    ["Numbers"] = 4
}

-- Función para restaurar aplicaciones a Spaces
function restoreSpaces()
    hs.alert.show("Restaurando configuración de Spaces...")
    
    -- Esperar a que el display se estabilice
    hs.timer.doAfter(3, function()
        for appName, spaceNumber in pairs(appSpaceConfig) do
            local app = hs.application.get(appName)
            if app then
                -- Mover la aplicación al Space correspondiente
                local wins = app:allWindows()
                for _, win in ipairs(wins) do
                    -- Intentar mover al Space (requiere permisos de accesibilidad)
                    hs.spaces.moveWindowToSpace(win, hs.spaces.allSpaces()[spaceNumber])
                end
            end
        end
        hs.alert.show("Spaces restaurados")
    end)
end

-- Detector de cambios de configuración de display
function displayWatcher(displayID, eventType)
    if eventType == "added" or eventType == "removed" then
        hs.alert.show("Cambio de display detectado")
        restoreSpaces()
    end
end

-- Iniciar el watcher
displayWatcherObj = hs.screen.watcher.new(displayWatcher)
displayWatcherObj:start()

-- Shortcut manual para restaurar (Control + Alt + Cmd + R)
hs.hotkey.bind({"ctrl", "alt", "cmd"}, "R", function()
    restoreSpaces()
end)

hs.alert.show("Hammerspoon configurado - Gestión de Spaces activa")
```

**Permisos necesarios**:
1. Ve a **Configuración del Sistema** → **Privacidad y Seguridad** → **Accesibilidad**
2. Añade **Hammerspoon** a las aplicaciones permitidas

**Script de gestión de Spaces**:

```bash
#!/bin/bash
# spaces_manager.sh

# Función para listar Spaces actuales
list_spaces() {
    yabai -m query --spaces | jq '.[] | {index, label, windows}'
}

# Función para mover aplicación a Space específico
move_app_to_space() {
    local app_name="$1"
    local space_index="$2"
    
    # Obtener window IDs de la aplicación
    window_ids=$(yabai -m query --windows | jq -r ".[] | select(.app == \"$app_name\") | .id")
    
    for window_id in $window_ids; do
        yabai -m window "$window_id" --space "$space_index"
    done
}

# Función de restauración completa
restore_all_spaces() {
    echo "Restaurando configuración de Spaces..."
    
    # Space 1: Comunicación
    move_app_to_space "Mail" 1
    move_app_to_space "Messages" 1
    move_app_to_space "Slack" 1
    
    # Space 2: Navegación
    move_app_to_space "Safari" 2
    move_app_to_space "Google Chrome" 2
    
    # Space 3: Desarrollo
    move_app_to_space "Code" 3
    move_app_to_space "Terminal" 3
    move_app_to_space "iTerm2" 3
    
    # Space 4: Productividad
    move_app_to_space "Microsoft Word" 4
    move_app_to_space "Microsoft Excel" 4
    
    echo "Restauración completada"
}

# Ejecutar función principal
case "$1" in
    list)
        list_spaces
        ;;
    restore)
        restore_all_spaces
